"title": "Исследование: периодический rebroadcast кошелька Bitcoin Core позволяет привязать адрес к IP узла, который его отслеживает"
"description": "В посте на Delving Bitcoin показано, что кошелёк Bitcoin Core повторно анонсирует неподтверждённую транзакцию, которую держит (отправленную или полученную), пирам по собственному таймеру через 12–36 часов, и этот сигнал детерминирован. Активный вариант: атакующий сам отправляет на уже использованный адрес небольшой платёж с низкой комиссией, который вряд ли быстро подтвердится, подключает свежего пира к каждому узлу-кандидату — и узел, повторно анонсировавший эту транзакцию, и есть тот, чей кошелёк отслеживает адрес. В симуляции автора на regtest привязка была верной во всех попытках; watch-only-кошелёк затронут так же, поскольку совпадение идёт по скрипту, то есть узел может не быть владельцем средств. Пассивная утечка известна давно, новизна — в активной постановке и надёжности привязки. Предложенный патч, ограничивающий rebroadcast только заново попавшими в mempool транзакциями, по словам автора не выпущен и не устраняет все пути утечки (например, при вытеснении транзакции из mempool и её повторной отправке кошельком)."
